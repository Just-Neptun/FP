\section{Solving Sudokus With Brainscales-2}

We will apply the simulated neurons to solve a given Sudoku problem. For an \( n \times n \) Sudoku grid, there are \( n^2 \) fields which could each be \( n \) different numbers. We will use \( n \) neurons for each field. These will each represent one of the possible output numbers, using a \quotedef{one hot encoding}.

We will use the Brainscales-2 system within Python to set up the neurons and synapses in order to solve the Sudoku. The created and used code is included as attached \texttt{.ipynb} and \texttt{.py} files.

The rules of Sudoku are encoded as constraints of the program. This means inhibitory synapses are set up so that spiking neurons inhibit activity in other neurons which would cause a disallowed board state.

These rules include:
\begin{itemize}
    \item Only one number per field
    \item Only one of each number per row
    \item Only one of each number per column
    \item Only one of each number within smaller grid boxes which cover the whole Sudoku
\end{itemize}

The implementation of these rules by connecting neurons is explained further in \autoref{sec:sudoku_counting_neurons}.

\subsection{Running Network with No Constraints}

As a \quoteapprox{control}, we will run the program on a \( 4 \times 4 \) Sudoku without implementing any constraint rules. The resulting \quoteapprox{solution} is shown in \autoref{fig:sudoku_no_constraints}.

\begin{figure}[htbp]
    \centering
    \includegraphics[width=0.7\textwidth]{./04 Sudoku/no_constraints_sudoku.png}
    \caption{Sudoku Solver Without Constraint Synapses}
    \label{fig:sudoku_no_constraints}
\end{figure}

Clearly, without implementing the actual rules/constraints of Sudoku, the solver is incomplete. The resulting grid contains multiple of the same number in the same row, column and box!

In the graph of the neuron activity on the right, we can see the initial clues given within the first \( \approx \qty{0.02}{\milli \second} \). These neurons are continually stimulated by the clue-giving neurons, so we see their activation is consistent and high throughout the solve.

Due to the Poisson noise stimulating every neuron, they all spike randomly during the whole process as well. There are no inhibitory synapses, so they do not influence each other or \quoteapprox{settle down} into a stable solution state.

We also note that the desired output (one-hot encoding) is not followed. Multiple neurons representing different numbers (different colors on the graph) in the same field (within the same thick horizontal lines) are firing at the same time.

\subsection{Running Network With Constraints}

After implementing the rules of Sudoku as inhibitory synapses in the network, we rerun the program, obtaining the solution seen in \autoref{fig:sudoku_with_constraints}.

\begin{figure}[htbp]
    \centering
    \includegraphics[width=0.7\textwidth]{./04 Sudoku/with_constraints_sudoku.png}
    \caption{Sudoku Solver With Constraint Synapses}
    \label{fig:sudoku_with_constraints}
\end{figure}

This time, the Sudoku is actually solved (as evident by inspection as well as the green border).

Again we can see the clues as constant spiking neurons in the activity graph. These inhibit other numbers from being activated within their fields. The \quoteapprox{deduced} numbers can be seen after at least \qty{0.04}{\milli \second}. These are less consistent spikes, but they even out towards the end as the simulation approaches the solution.

We also note the small number of \quoteapprox{misfires}, were a neuron representing a different number fires, even though a different number is correct. This sometimes happens even if that number was already deduced, or is given as the clue. This is caused by the Poisson noise, which also allows the system to work at all, so it is necessary and expected. Luckily, these neurons do not continuously activate. They are quickly inhibited by the other neurons again, so their effects do not cause the solution to fail.

\subsection{Implementation and Counting Required Neurons and Synapses}
\label{sec:sudoku_counting_neurons}

We set up neurons to represent the board state. We also use additional neurons to add random noise to the calculation (this avoids dead-ends where a mistake in the solve happened). These are connected by synapses.

In order to sustain activity and \quoteapprox{save} a value when a number is determined, neurons are linked to themselves.

The constraints/rules of the Sudoku are encoded in other synapses between different groups of neurons.

These will be explained for a \( 4 \times 4 \) and a \( 9 \times 9 \) Sudoku grid. The exact number of neurons and synapses needed will be calculated as well.
